# Phase 3 — generality and bench validation

**This folder is separate from `extended/` and from the frozen run, deliberately.**

Phase 2 (`extended/`) asked whether the frozen SH3 model survives contact with external data. It
does, with one claim withdrawn. Phase 3 asks a different question — whether anything here generalises
beyond SH3 — and mixing the two would make it impossible to say which phase a number came from.

| | |
|---|---|
| `H1` | a second domain family — **done**: H1.0 audit, H1.1 pre-registration, H1.2 evaluation, H1.3 assay-quality follow-up |
| `H2` | bench validation of the G4 panel — **not started**; needs a collaborator, not compute |

**Phase 3 results are provisional and are not in the manuscript.** The promotion rule below is the
reason: a finding moves into `extended/docs/` or the paper once it stands on its own, and H1's main
arm is inconclusive.

## The isolation rule

1. **Phase 3 writes only inside `phase3/`.** It never writes to `results/`, `extended/`, `docs/` or
   `notebooks/` at the repository root.
2. **It reads the earlier phases freely** — the frozen run and `extended/` are inputs, and the frozen
   run stays read-only as it has throughout.
3. **No number from Phase 1 or Phase 2 is recomputed here.** If a Phase 3 program needs a frozen
   value it re-derives it and asserts the match, which is the convention every extended program
   followed.
4. **Conclusions stay separate until they are earned.** A Phase 3 result is reported in
   `phase3/docs/`, and only promoted into `extended/docs/OUTCOMES.md` or the manuscript once it
   stands on its own.

## Conventions carried over

- **Pre-registration before the notebook**, for any program with a pass/fail verdict. Committed to
  git first, so the timestamp proves the order. `docs/preregistration/`.
- **A leakage audit before any comparison**, not after. E3 disqualified ThermoMPNN by finding 13 of
  15 held-out domains inside its published training split — *before* running it. H1's first task is
  the same question about PDZ.
- **Three documents per program, and they do different jobs.** Mixing them is how a source becomes
  unciteable and a method becomes folklore:

  | file | contains | must not contain |
  |---|---|---|
  | `METHODS_<ID>.md` | **every source declared** — path, size, MD5, date, upstream citation and licence — and the methodology: each step, every threshold with its justification, the assertions, and how to re-run it | interpretation, or any claim about what the result means |
  | `ANALYSIS_<ID>.md` | the interpretation: what the numbers mean, what is licensed as a claim, what is not, and the limitations | undeclared sources, or a parameter that appears nowhere in METHODS |
  | `RESULTS_<ID>.md`, `metrics_<ID>.json` | machine-written, nothing typed by hand | anything a human edited |

  A threshold that appears in `ANALYSIS` but not in `METHODS` is a threshold chosen after seeing the
  result. Keeping them apart makes that visible.
- **Assert what a join keeps.** Three defects in Phase 2 were inner merges that lost most of their
  rows silently.
- **Per-variant tables stay out of git** — `*.tsv`, `*.parquet` and `*.gz` are already ignored.
