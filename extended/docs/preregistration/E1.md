# E1 — The rules, written down before we look

*(Decisions taken 27 Sep 2026 — see Part 6, which governs. Awaiting sign-off.)*

## What this file is for

E1 asks two questions:

1. **When our model says a variant breaks the protein, do doctors' databases agree it causes disease?**
2. **Do healthy people carry fewer protein-breaking variants than chance would predict?**

There are several reasonable ways to set up these tests. So we run **six experiments**, each a
slightly different setup, and **compare them at the end**. Everything — every experiment, which one
gives the verdict, and how the comparison will be read — is decided **now**, before any result
exists. This file is committed to git first (git timestamps it), and only then is the notebook
written.

Once committed, this file is never edited. If something must change, we add a dated note explaining
why, and still report the original plan's results.

**So far:** nothing has been run. No prediction has been compared with any clinical label.

## Part 1 — Rules shared by every experiment

### The data, pinned
- **ClinVar** (disease labels): downloaded 26 Sep 2026, fingerprint `0ef1c60048748efe12ea3120ecc848ce`
- **gnomAD v4** (how common each variant is in healthy people): as downloaded by X0
- **Our "breaks the protein" call:** `fold_lo ≥ 1`, exactly as defined in B3. Never adjusted.

### Which ClinVar variants count
- **Only single-letter protein changes** (missense).
- **Disease-causing:** *Pathogenic* or *Likely pathogenic*.
- **Harmless:** *Benign* or *Likely benign*.
- Everything else (*Uncertain*, *Conflicting*, *risk factor*…) is left out.
- ⚠ ClinVar gives *conflicting* labels 1 star. We exclude them by label, so the star rule never lets
  them in.

**How much we trust a label** — ClinVar's star rating:

| Stars | Meaning |
|---|---|
| 0 | Asserted, with no stated reasoning |
| 1 | One lab, with stated reasoning |
| 2 | Several labs, all agreeing |
| 3–4 | Expert panel or official guideline |

### What counts as "common in healthy people"
Found in more than a set share of people (1 in 100, or 5 in 100 — see the experiments), using
gnomAD's cautious estimate for the population that carries it most often. It must not be labelled
disease-causing in ClinVar.

If that cautious estimate is missing from our download, we use the plain overall frequency, from at
least 20,000 people tested, and say so in the report.

### What counts as a yes
- **Question 1:** disease-causing variants are flagged more often than harmless ones —
  statistically clear (p < 0.025) and in the right direction.
- **Question 2:** common variants are flagged less often than chance predicts, with "chance"
  calculated exactly as in B6 (which found 5.9 % against 9.2 % expected in cancer) — p < 0.025.
- **Too few to judge:** fewer than **20** variants in a group → numbers shown, **no verdict**.
- We always report *how big* each difference is, not only whether it exists.

*(0.025 instead of the usual 0.05 because there are two questions.)*

## Part 2 — The six experiments

Each experiment answers **both** questions. Each changes **one thing** from Experiment 1, so any
difference in the result can be traced to that one change.

| Exp | Variants we have predictions for | ClinVar stars | "Common" means | Disagreeing labels | What it tests |
|---|---|---|---|---|---|
| **1 — MAIN** | **All SH3 variants** ¹ | **1+** | **> 1 in 100** | **left out** | The main answer |
| 2 | All SH3 variants | **2+** | > 1 in 100 | left out | Does it hold with only well-agreed labels? |
| 3 | All SH3 variants | **0+** | > 1 in 100 | left out | What happens if we trust every label? |
| 4 | All SH3 variants | 1+ | **> 5 in 100** | left out | Does it hold with the strict clinical cut-off? |
| 5 | All SH3 variants | 1+ | > 1 in 100 | **X0's rule** ² | Does the way we settle disagreements matter? |
| 6 | **Cancer atlas only** ³ | 1+ | > 1 in 100 | left out | Does it hold using only the original predictions? |

¹ Our existing, unchanged model is run on every missense variant in an SH3 domain found in ClinVar
or gnomAD. This changes no published number, but may need a GPU.

² X0 kept the highest-rated label and, if tied, the more severe one.

³ The 6,884 atlas cancer variants, which already have predictions. No new model runs.

**If Experiment 1 cannot be run** (no GPU access, or the model cannot score the new variants),
**Experiment 6 becomes the main experiment** and this is stated in the report. Decided now, so it
cannot be chosen later because it looks better.

### Why these values for the main experiment
- **1+ stars** is what most published studies use; 2+ is usually a check.
- **1 in 100** rather than 1 in 1,000, because some real disease variants reach 1 in 1,000 (e.g. in
  cystic fibrosis), so the lower cut-off would call real disease variants "harmless".
- **Leaving disagreeing labels out** avoids picking a winner between "disease" and "harmless".

### How the table will be read — decided now

1. **The verdict is Experiment 1's.** Always — even if another experiment looks better.
2. **Robust:** every experiment with enough data agrees with Experiment 1 → the result does not
   depend on our choices. We say so.
3. **Depends on a choice:** one or more experiments disagree → we name which choice flips it (for
   example, "the result holds at 1+ stars but not at 2+"). That is reported as a finding, not
   hidden.
4. **No experiment is ever promoted to main after seeing results.**

Anything not listed in this file is exploratory and labelled as such.

## Part 4 — Known weaknesses, admitted in advance

- **Some overlap is built in.** ClinVar labels partly rest on computer predictions and on how common
  a variant is. So some agreement with our model, and with gnomAD, is expected even from a mediocre
  model.
- **Not every disease works by breaking the protein.** Some variants cause disease by giving the
  protein a new behaviour or blocking its partner. Our model should miss those by design, so a weak
  Question 1 may reflect that, not a model error.
- **Experiment 6 may be too small.** Few healthy-population variants appear in a cancer atlas, so its
  Question 2 may return "too few".

## Part 5 — Review before sign-off (27 Sep 2026)

Three things were checked against the actual data before this file is signed. Each needs a decision;
none can be left to be discovered after a result exists.

### 5.1 The counts change what Experiments 2 and 6 can deliver

The table above was empty when this file was drafted. Filled in, it says:

| Experiment | Disease-causing available | Can it give a Q1 verdict? |
|---|---|---|
| **1 — main** (1+ stars) | **21** | **yes, barely** — 21 vs 126, just over the 20 floor |
| 2 (2+ stars) | 4 | **no** — reports "too few", by this file's own rule |
| 3 (0+ stars) | 29 | yes |
| 4, 5 (Q2 variants only) | 21 | as Experiment 1 |
| 6 (atlas only) | 3 | **no** |

Two consequences:

- **Experiment 2 is now a check that cannot return a verdict.** It still runs and is still reported —
  "too few to judge" is information — but it cannot corroborate or contradict Experiment 1. Expect
  the robustness table to read "too few" there.
- **⚠ The stated fallback does not work.** This file says that if Experiment 1 cannot run,
  Experiment 6 becomes the main experiment. Experiment 6 has **3** disease-causing variants, so it
  cannot answer Question 1 at all.

**Decision required.** Either (a) Experiment 3 (0+ stars, 29 variants) becomes the fallback, accepting
unreviewed labels and saying so, or (b) Question 1 is reported as under-powered whenever Experiment 1
cannot run. Pick one now, write it here, and cross out the Experiment 6 fallback in Part 2.

Note that Experiment 1 **is** runnable: 27,505 new variants is roughly ten minutes of GPU time, far
short of a blocker. The fallback is a contingency, not the expected path.

### 5.2 The primary definition of "common" cannot be computed from our data

Part 1 defines common as *"gnomAD's cautious estimate for the population that carries it most often"*
— that is popmax, or the filtering allele frequency. **X0's gnomAD export does not contain it.** The
columns are `gene, variant_id, wt_aa, pos_protein, mut_aa, ac, an, af` — combined counts only.

As written, the fallback would fire for every variant, which means the primary definition is
decorative.

**Decision required.** Either (a) re-fetch gnomAD with `popmax`/`faf95` added to the GraphQL query —
a small change to X0, a few minutes of API time — or (b) make combined AF the primary definition and
delete the popmax sentence. Option (a) is better: popmax is the standard, and combined AF
under-states frequency in any variant concentrated in one population.

### 5.3 Power is the real limitation, and it should be stated as the headline caveat

21 disease-causing against 126 harmless is enough for a rank test to detect a **large** effect and
nothing smaller. That is not a flaw in the design — it is what the data contains — but the report
must lead with it rather than bury it. SH3 domains are simply not a well-annotated clinical target:
3,735 ClinVar missense records across 310 domains, of which 29 are pathogenic at any confidence.

This makes the **continuous** comparison (predicted ΔΔG distributions across the four groups) more
informative than the **rate** comparison (what fraction is called destabilising), because it uses
every variant rather than collapsing to a proportion. Both are already specified in Part 2; the
report should present the continuous one first.

## Part 6 — Decisions taken, 27 Sep 2026

The open points in Part 5 are now resolved. This section is the operative plan; where it differs
from Parts 2–3, this section governs.

### 6.1 Structure: three arms with a verdict, two reported as counts only

| Arm | ClinVar stars | "Common" | Verdict? | Why it is here |
|---|---|---|---|---|
| **1 — MAIN** | 1+ | popmax > 1 in 100 | **yes** | the answer |
| **3** | 0+ | popmax > 1 in 100 | yes | does it hold if every label is trusted? |
| **4** | 1+ | popmax > 5 in 100 | yes | does it hold at the strict clinical cut-off? |
| 2 | 2+ | popmax > 1 in 100 | **no — 4 variants** | reported as counts; the sizes are the finding |
| 6 | atlas only | popmax > 1 in 100 | **no — 3 variants** | reported as counts |

Arms 2 and 6 are **not deleted**. They run, their group sizes and raw numbers are printed, and the
report states that no verdict is possible. That the strictest evidence tier contains four
pathogenic SH3 variants is itself worth saying.

**Experiment 5 (X0's conflict rule instead of excluding conflicts) is dropped.** Reason recorded
now: ClinVar labels *Conflicting* at 1 star, and arms 1, 3 and 4 already exclude conflicting records
by label, so arm 5 would differ from arm 1 only in records that all three other arms exclude by
construction. It tests a choice that the main design does not make.

### 6.2 No fallback arm

Part 2 said Experiment 6 becomes the main experiment if Experiment 1 cannot run. **That is
withdrawn, and not replaced.**

Experiment 3 cannot serve either: it also scores *all SH3 variants*, so it needs exactly the same
inference as Experiment 1. A fallback that shares the blocker is not a fallback.

**If the frozen head cannot score the new variants, E1 is postponed** — not substituted. Stated now
so that a weaker design cannot be adopted later because it happens to be runnable.

### 6.3 Power, stated in advance

**21 disease-causing against 126 harmless detects a large effect and nothing smaller.** Any null
result in Question 1 is therefore ambiguous between "the calls do not track pathogenicity" and "this
test could not have seen it", and the report must say so rather than reporting a null as evidence of
absence.

Consequences, fixed now:

- The **continuous** comparison (predicted ΔΔG distributions across groups) is the primary
  presentation, because it uses every variant; the **rate** comparison (fraction called
  destabilising) is secondary, because collapsing 21 variants to a proportion discards most of what
  little information there is.
- Effect size with a confidence interval is reported for every comparison, verdict or not.
- No post-hoc power calculation. The numbers above were known before any result existed.

### 6.4 "Common" is popmax, and X0 will be extended to provide it

Confirmed against the gnomAD v4 API: `exome { faf95 { popmax popmax_population } populations { id ac an } }`
are both available. X0's query gains them, and the gnomAD cell is re-run.

- **Primary:** `faf95.popmax` — gnomAD's own filtering allele frequency, the conservative estimate.
- **When `faf95` is null** (it is computed only above a frequency floor, so it is null for most rare
  variants): the maximum of `ac/an` across populations with `an ≥ 2000`, to avoid tiny denominators.
- **Neither available:** combined AF, flagged in the output column `af_source`, and the count of
  such variants reported.

### 6.5 Attestation — no predictions were consulted

Required by Part 4's rule that counting is allowed but looking at predictions is not.

**Confirmed.** The counting script read three files: `SH3_cancer_master.tsv` (columns `gene`,
`uniprot`, `domain_idx`, `dom_start`, `dom_end`, `pos_protein`, `wt_aa`, `mut_aa`),
`clinvar_sh3.csv` (labels and review status) and `gnomad_sh3_missense.csv` (`ac`, `an`, `af`). None
contains a prediction column. `pred_ddG_fold` and `fold_lo` were never loaded, and no statistic
relating any prediction to any clinical label has been computed or displayed.

**One caveat, stated rather than glossed.** `results/X0_external_data/atlas_with_external.csv`
(2.7 MB) was written by X0 *before* this pre-registration was drafted, and it does contain
`pred_ddG_fold` beside `clinvar_sig`. The file exists; nothing has been run against it. The
guarantee here is that the relationship has not been examined, not that it was impossible to
examine.
